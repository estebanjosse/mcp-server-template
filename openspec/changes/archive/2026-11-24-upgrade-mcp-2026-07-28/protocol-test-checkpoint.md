# Task 2.2 — Pre-upgrade protocol expectations

The existing C#/xUnit host suites now exercise precise protocol expectations against the application rather than replacing its transport or configuring a test-only session policy. Wire expectations are pinned to [the SDK v2.4.0 HTTP conformance tests](https://github.com/modelcontextprotocol/csharp-sdk/blob/v2.4.0/tests/ModelContextProtocol.AspNetCore.Tests/July2026ProtocolHttpHandlerTests.cs), its Streamable HTTP handler, and its `DiscoverResult` and `McpServerImpl` implementations.

On SDK 1.3.0 the focused host suites produced the intentional RED checkpoint: HTTP 37 passed and 11 failed after the review corrections; the unchanged stdio suite had 49 passes and 1 failure. The HTTP assertions pin the unsupported-version `requested` and `supported` payload (including malformed legacy `initialize`), and distinguish stateless endpoint routing from handler rejection: SDK v2.4.0's `McpEndpointRouteBuilderExtensions` maps neither GET nor DELETE in stateless mode. HTTP rejected modern headers without the new correlated error shape, issued session IDs for legacy initialization, and rejected GET/DELETE before reaching modern method handling. Stdio negotiated both historical revisions and returned the legacy prompt-list shape, but returned method-not-found for modern discovery. This was the expected pre-upgrade result. Independent counter-review passed on `fcd6c0c`; after task 2.3, the same suites passed all 48 HTTP and 50 stdio tests.
